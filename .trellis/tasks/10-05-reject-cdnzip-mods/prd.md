# PRD：订阅/启用 CDN-zip 型模组时面板明确拒绝并提示原因

> 任务方向变更（2026-10-05 用户决策）：原「SeedUgcCache 自动本地化」方向否决——
> 用户弃用全部 CDN-zip 模组，防线收紧为入口拒绝。背景与完整事故链见
> `.trellis/spec/backend/dst-mod-management.md`（CDN-zip 出路 + 客户端必装边界 + 写入者契约）。

## 背景

CDN-zip 型老模组（Steam GetDetails `filename == "mod_publish_data_file.zip"`）在
box64/steamclient 环境**永远无法被游戏认定为已安装**（C4：steamclient 是最终裁决者）
→ 每次世界启动游戏都联网重下 → 慢且不稳，实测引发 Master 启动期无声死亡连环事故
（2026-10-05，排查一晚）。

现有防线（2026-09-21 上线）只覆盖**发现**环节：搜索默认过滤 + 按 ID 直查标记警告。
**订阅下载与启用两个入口不设防**——用户按 ID 订阅后仍可启用进 modoverrides，
踩"启动死亡 → 无应答"全套坑后才能发现。

## 需求

1. **订阅入口拒绝**：`SubscribeModByModId`（PUT /api/mod/:id）在 GetDetails 后判定
   CDN-zip（复用 `internal/service/mod/cdn_zip.go` 分类器），命中即返回明确错误，
   不下载、不落库。文案需可操作，例如：
   `"该模组（<id> <名称>）为 CDN-zip 型老模组，当前 box64 运行环境下游戏无法加载
   （每次启动重复联网下载且可能导致世界启动失败），面板已停止支持。请在创意工坊
   寻找同功能的新版模组。"`
2. **启用侧兜底**：世界配置保存（modoverrides 重写路径）若启用清单含 CDN-zip 型
   （DB 可能存有历史记录），保存被拒并列出全部涉事 mod 名称与 ID。
3. 判定逻辑单一事实源：两处拒绝复用同一分类函数，判定所需 GetDetails 数据
   已在现有流程中取得，不新增网络调用。

## 验收标准

1. 单测：分类器复用断言、订阅拒绝路径（CDN-zip 命中 → 错误文案含 ID 与原因、
   不落库不下载）、正常模组订阅不受影响
2. 真机：按 ID 订阅 661253977 → 明确报错、DB 无新记录、备份库无新目录；
   订阅正常模组照常成功
3. 回归：搜索默认过滤、按 ID 直查的 ⚠️ 警告标记行为不变

## 非目标

- `mods/local-<id>/` 已有本地模组的管理（用户自有安排，2026-10-05 已全部停用）
- 自动本地化转换（原方向，用户已否决）
- 347079953/362175979 等历史 DB 记录的清理（另行处理）
